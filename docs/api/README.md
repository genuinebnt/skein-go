# Skein API

The public API is what the gateway serves to browsers: REST/JSON for
requests and WebSockets for live streams ([ADR-0002](../adr/0002-contracts-grpc-rest-websocket.md)).
Behind the gateway every route is a gRPC call. The `.proto` files in
`proto/skein/v1` are the source of truth for both; these pages explain them
and give examples.

| Page | Service | What it covers |
|---|---|---|
| [identity.md](identity.md) | `IdentityService` | Sign-up, sessions, users, workspaces, members, note roles, share links, replica registration |
| [documents.md](documents.md) | `DocumentService` | Notes, CRDT operations, history, diff, blame, undo and redo |
| [search.md](search.md) | `SearchService` | Text, regex and code search, title suggestions |
| [graph.md](graph.md) | `GraphService` | Link graph, graph analysis, blast radius, paths, reading plans |
| [ml.md](ml.md) | `MLService` | Semantic search, related notes, clusters, clustering benchmarks |
| [agent.md](agent.md) | `AgentService` | Chats, runs, confirmations |
| [notifications.md](notifications.md) | `NotificationService` | Inbox and preferences |
| [websocket.md](websocket.md) | streaming RPCs | Live sync, agent output, live notifications |

The machine-readable description is
[`gen/openapi/skein.swagger.json`](../../gen/openapi/skein.swagger.json)
(OpenAPI 2.0, generated by `make proto`). It covers every REST route; the
WebSocket endpoints are only described here.

## Where the pieces live

```
proto/skein/v1/*.proto      contracts, REST mapping (google.api.http), OpenAPI options
proto/third_party/          vendored google.api and openapiv2 option protos
buf.gen.yaml                Go, gRPC, grpc-gateway and OpenAPI generation
scripts/gen-python.sh       Python generation (grpcio-tools)
gen/go/                     Go module github.com/genuinebnt/skein-go/gen/go (committed)
gen/python/                 Python package skein-proto, import name skein_proto (committed)
gen/openapi/                the merged OpenAPI document (committed)
docs/api/                   these pages
```

`make proto` regenerates everything; CI fails if the committed `gen/` is
stale. `gen/go/contracttest` checks that the routes, the OpenAPI document and
these pages agree, including that every JSON example below parses as the
message it is labelled with.

Which RPCs are reachable over REST:

- **User-facing unary RPCs** have exactly one route each.
- **Streaming RPCs** (`DocumentService.Sync`, `AgentService.SendMessage`,
  `NotificationService.Subscribe`) are WebSocket endpoints, because
  grpc-gateway cannot serve them to browsers ([websocket.md](websocket.md)).
- **Internal RPCs** (`IdentityService.Authorize`, `ListReadableNotes`,
  `IssueDelegatedToken`) have no route. Only other services call them, and the
  gateway refuses any path that is not in the OpenAPI document.

## Conventions

### Paths

- Everything is under `/v1`, the version of the `skein.v1` proto package.
- Resources are plural nouns, nested under their owner when they only make
  sense inside it: `/v1/workspaces/{workspaceId}/notes`, then `/v1/notes/{noteId}`
  once a note has its own globally unique ID.
- Standard methods use HTTP verbs: `GET` reads, `POST` on a collection
  creates, `PUT` sets a whole value (a role, preferences), `DELETE` removes.
- Actions that are not create, read, update or delete are **custom methods**:
  `POST /v1/notes/{noteId}:restore`, as in [Google AIP-136](https://google.aip.dev/136).
  A few reads that need a structured argument (a version vector) are custom
  methods too (`:textAt`, `:diff`); they change nothing and are safe to retry.
- Path variables are UUIDv7 strings unless the page says otherwise.

### JSON

JSON is the [proto3 JSON mapping](https://protobuf.dev/programming-guides/json/),
which is what grpc-gateway emits:

| Proto | JSON | Example |
|---|---|---|
| field `note_id` | `noteId` (lowerCamelCase) | `"noteId": "01936f40-..."` |
| `uint64`, `int64` | decimal **string** (JavaScript numbers lose precision past 2^53) | `"replicaId": "4831727201934127107"` |
| `uint32`, `int32`, `double` | number | `"maxHops": 3` |
| `bytes` | standard base64 string | `"ops": "AQIDBA=="` |
| enum | value name | `"role": "WORKSPACE_ROLE_MEMBER"` |
| `google.protobuf.Timestamp` | RFC 3339 string in UTC | `"createdAt": "2026-11-16T09:30:00Z"` |
| `map<string, V>` | object | `"hops": {"01936f40-...": 0}` |

Fields with default values (empty string, 0, false, empty list) are omitted
from responses. Clients must treat a missing field as its default, and must
ignore fields they do not know, so new fields can be added without a new
version. Text ranges are code points ([ADR-0003](../adr/0003-text-positions.md));
the browser converts to UTF-16.

### Query parameters

For `GET` and `DELETE`, request fields that are not in the path are query
parameters with their JSON names. Nested fields use dots and repeated fields
repeat the parameter:

```
GET /v1/workspaces/{workspaceId}/search?query=raft&mode=SEARCH_MODE_TEXT&languages=go&languages=rust&page.pageSize=20
```

For `POST` and `PUT`, the body is the request message without its path
fields. A request with no other fields still sends `{}`.

### Pagination

List methods take a `page` (`PageRequest`) and return a `page`
(`PageResponse`):

```
GET /v1/workspaces/{workspaceId}/notes?page.pageSize=50
GET /v1/workspaces/{workspaceId}/notes?page.pageSize=50&page.pageToken=CgwIgICAgICAgICAARIA
```

- `pageSize` is a maximum. 0 means the server default (50); larger than the
  server maximum (500) is clamped, not refused.
- `nextPageToken` is opaque, and is absent on the last page. Pass it back
  unchanged with the same other parameters; changing them is
  `INVALID_ARGUMENT`.
- Pages are cursor-based, so items created while paging do not shift later
  pages.

### Errors

A failed request returns an HTTP status and a
[`google.rpc.Status`](https://github.com/googleapis/googleapis/blob/master/google/rpc/status.proto)
body (grpc-gateway's standard error format):

```json
{
  "code": 3,
  "message": "title must not be empty",
  "details": [
    {
      "@type": "type.googleapis.com/google.rpc.BadRequest",
      "fieldViolations": [
        {"field": "title", "description": "must not be empty"}
      ]
    },
    {
      "@type": "type.googleapis.com/google.rpc.RequestInfo",
      "requestId": "01936f80-6f70-7a81-9ba3-1e2f30415263"
    }
  ]
}
```

`code` is the gRPC status code; `message` is for developers, not end users;
`details` holds typed [error details](https://github.com/googleapis/googleapis/blob/master/google/rpc/error_details.proto).
Every error carries `RequestInfo` with the request ID.

| gRPC code | HTTP | Meaning here | Details to expect |
|---|---|---|---|
| `INVALID_ARGUMENT` (3) | 400 | Malformed request, bad field value | `BadRequest` |
| `FAILED_PRECONDITION` (9) | 400 | Valid request, wrong state (confirming an answered confirmation) | `PreconditionFailure` |
| `OUT_OF_RANGE` (11) | 400 | A version or offset past the end | `BadRequest` |
| `UNAUTHENTICATED` (16) | 401 | Missing, invalid or expired access token | `ErrorInfo` with reason `TOKEN_EXPIRED` or `TOKEN_INVALID` |
| `PERMISSION_DENIED` (7) | 403 | Authenticated, but not allowed | `ErrorInfo` with reason `ACTION_NOT_ALLOWED` |
| `NOT_FOUND` (5) | 404 | No such resource, or one the caller may not know exists | `ResourceInfo` |
| `ALREADY_EXISTS` (6) | 409 | Unique value taken (email, replica ID) | `ResourceInfo` |
| `ABORTED` (10) | 409 | Concurrency conflict; retry | `ErrorInfo` |
| `RESOURCE_EXHAUSTED` (8) | 429 | Rate limit or quota | `QuotaFailure`, `RetryInfo` |
| `CANCELLED` (1) | 499 | The client went away | |
| `INTERNAL` (13), `UNKNOWN` (2), `DATA_LOSS` (15) | 500 | A bug or an unexpected failure | |
| `UNIMPLEMENTED` (12) | 501 | Not built yet | |
| `UNAVAILABLE` (14) | 503 | Temporarily down; retry with backoff | `RetryInfo` |
| `DEADLINE_EXCEEDED` (4) | 504 | Took too long | |

Notes the caller cannot read are reported as `NOT_FOUND`, not
`PERMISSION_DENIED`, so IDs cannot be probed. Messages never contain note
contents or secrets.

### Authentication

Send the access token from sign-in, sign-up or refresh on every request:

```
Authorization: Bearer EXAMPLE_ACCESS_TOKEN
```

Only `POST /v1/users`, `POST /v1/sessions`, `POST /v1/sessions:oauth`,
`POST /v1/sessions:refresh` and `POST /v1/sessions:signOut` work without one.
Access tokens live for minutes; when a request fails with `UNAUTHENTICATED`
and reason `TOKEN_EXPIRED`, refresh once and retry. WebSockets authenticate
differently, see [websocket.md](websocket.md#authentication).

### Idempotency keys

`POST` requests accept an `Idempotency-Key` header, a client-generated
unique string (a UUID is ideal, at most 255 characters):

```
POST /v1/workspaces/01936f3e-1a2b-7c3d-8e4f-5a6b7c8d9e0f/notes
Idempotency-Key: 6f1c2e8a-3b4d-4c5e-9f60-718293a4b5c6
```

The gateway stores the first response for 24 hours per caller and key, and
replays it for any retry with the same key, with the header
`Idempotent-Replayed: true`. Reusing a key with a different method, path or
body is `INVALID_ARGUMENT`; a retry that arrives while the first is still
running gets `ABORTED` and should be retried after a moment. Send a key on
every `POST` that creates something or is not naturally idempotent (creating
notes, workspaces, chats or share links; undo and redo). `GET`, `PUT` and
`DELETE` are idempotent by definition and ignore the header; so are
`ApplyOps` (CRDT operations apply once) and `MarkRead`.

### Request IDs and tracing

Every response carries `X-Request-Id`. A client may send its own (at most
128 characters of `[A-Za-z0-9-_.]`); otherwise the gateway generates a
UUIDv7. The ID is logged by every service the request touches and appears in
error details. The gateway also accepts and propagates W3C `traceparent` and
`tracestate` headers, so a browser trace continues through the backend.

### Rate limits

The gateway limits each user and each IP address with GCRA, in separate
budgets for general requests, search, sync traffic and agent runs. Every
response carries the current budget, following the IETF
[RateLimit header fields](https://datatracker.ietf.org/doc/draft-ietf-httpapi-ratelimit-headers/):

| Header | Meaning | Example |
|---|---|---|
| `RateLimit-Limit` | Requests allowed per window in the budget this request used | `100` |
| `RateLimit-Remaining` | Requests left in the current window | `42` |
| `RateLimit-Reset` | Seconds until the budget is fully replenished | `17` |
| `Retry-After` | On 429 only: seconds to wait before retrying | `3` |

A request over the limit gets `429` with `RESOURCE_EXHAUSTED`, a
`QuotaFailure` naming the budget, and `RetryInfo`. Back off for at least
`Retry-After` seconds, with jitter.

### Versioning

The version is in the path (`/v1`) and matches the proto package
(`skein.v1`). Within a version, changes are additive only: new routes, new
optional fields, new enum values. `buf breaking` enforces this on the
contracts in CI. Clients must therefore ignore unknown fields and handle
unknown enum values (treat them as `..._UNSPECIFIED`).

A breaking change creates `skein.v2` and `/v2`, served alongside `/v1` until
clients have moved; deprecated routes are marked `deprecated` in the OpenAPI
document and get a `Deprecation` header before removal.
